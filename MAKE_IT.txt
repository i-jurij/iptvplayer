## План устранения ошибок в парсере EPG

### 1. Устранение дублирования программы при добавлении в канал
**Файл:** `EPGParserExpat.cpp`  
**Метод:** `OnEndElement` (обработчик закрывающего тега `programme`)

**Проблема:** программа добавляется дважды (или более) из-за вложенных циклов и дублирующих вызовов `push_back`.

**Действия:**
- Удалить внутренний цикл поиска канала и лишнюю проверку `stopTime > 0`.
- Оставить один блок поиска канала по `channelId` и одно добавление программы.
- Добавить проверку, что `startTime > 0` и `title` не пусто.

**Итоговый код:**
```cpp
if (name == "programme") {
    if (!m_currentProgram.channelId.empty() &&
        !m_currentProgram.title.empty() &&
        m_currentProgram.startTime > 0) {
        for (auto &ch : m_channels) {
            if (ch.id == m_currentProgram.channelId) {
                ch.programs.push_back(m_currentProgram);
                break;
            }
        }
    } else {
        LOG_WARN("EPGParserExpat: Skipped programme with missing data");
    }
    m_state = STATE_NONE;
}
```

### 2. Исправление парсинга времени без указания временной зоны
**Файл:** `EPGData.h`  
**Функция:** `EpgTime::ParseXmltvTime`

**Проблема:** если зона отсутствует, время интерпретируется как локальное и затем преобразуется в UTC через `MakeUTC()`, что приводит к неправильному смещению.

**Действия:**
- Если `zonePart` пуста, считать время уже UTC (не применять `MakeUTC()`).
- Создавать `wxDateTime` сразу в UTC, если зона не указана.
- Если зона указана, парсить смещение и применять его к UTC времени.

**Итоговый код (фрагмент):**
```cpp
if (zonePart.empty()) {
    wxDateTime dt(day, static_cast<wxDateTime::Month>(month-1), year,
                  hour, minute, second, wxDateTime::UTC);
    if (dt.IsValid()) return dt.GetTicks();
    return 0;
}
// ... обработка зоны ...
```

### 3. Удаление избыточной проверки `stopTime > 0`
**Файл:** `EPGParserExpat.cpp` (в той же функции `OnEndElement`)

**Проблема:** программа добавлялась независимо от `stopTime`, но внутри была проверка, которая ни на что не влияла.

**Действия:**  
- Убрать проверку `m_currentProgram.stopTime > 0` (оставить только проверку на `startTime > 0`).  
- Добавить опциональную проверку `stopTime > startTime`, чтобы отсеивать некорректные интервалы (можно залогировать предупреждение).

---

### 4. Очистка состояния текущей программы
**Файл:** `EPGParserExpat.cpp`  
**Метод:** `OnStartElement` (обработчик открывающего тега `programme`)

**Проблема:** поля `m_currentProgram` не сбрасываются явно, поэтому при отсутствии какого-либо атрибута в XML может сохраниться значение от предыдущей программы.

**Действия:**  
- В блоке `if (name == "programme")` инициализировать `m_currentProgram = EpgProgram();` (или обнулить все поля).

---

### 5. Валидация атрибутов `start` и `stop`
**Файл:** `EPGParserExpat.cpp`  
**Метод:** `OnStartElement`

**Проблема:** если атрибуты `start` или `stop` отсутствуют или имеют неверный формат, `ParseXmltvTime` вернёт `0`, что приведёт к пропуску программы без уведомления.

**Действия:**  
- После парсинга `startTime` проверить, что значение > 0. Если нет, залогировать предупреждение и не создавать программу (или не добавлять её позже).

---

### 6. Указание кодировки при создании парсера
**Файл:** `EPGParserExpat.cpp`  
**Метод:** `Parse`

**Проблема:** `XML_ParserCreate(nullptr)` использует кодировку по умолчанию, что может вызвать проблемы с некоторыми XMLTV-файлами.

**Действия:**  
- Заменить на `XML_ParserCreate("UTF-8")` для явного указания кодировки.

---

### 7. Добавление логирования предупреждений
**Файл:** `EPGParserExpat.cpp`  
**Методы:** `OnEndElement` и `OnStartElement`

**Проблема:** при пропуске программ из-за отсутствия данных нет информативных сообщений, что затрудняет отладку.

**Действия:**  
- Добавить вызовы `LOG_WARN` при пропуске программы (нет `channelId`, нет `title`, `startTime == 0`).  
- При парсинге времени с ошибкой добавить `LOG_DEBUG` или `LOG_WARN`.

---

### 8. Обработка случая, когда программа встречается до объявления канала
**Файл:** `EPGParserExpat.cpp`  
**Метод:** `OnEndElement`

**Проблема:** если в XMLTV порядок нарушен (сначала `programme`, потом `channel`), программа не будет добавлена.

**Действия:**  
- Вместо немедленного добавления можно сохранять программы во временный список, а после завершения парсинга привязать их к каналам.  
- Или, как минимум, добавить проверку: если канал ещё не зарегистрирован, оставить программу в ожидании (но это усложнит логику).  
- На практике большинство XMLTV-файлов соблюдают порядок, поэтому можно оставить как есть, но добавить комментарий.

---

### 9. Проверка размера распакованных данных
**Файл:** `EPGManager.cpp`  
**Функция:** `DecompressIfNeeded`

**Проблема:** защита от zip-бомб есть (1 ГБ), но нет проверки на слишком маленький размер (0 байт) после распаковки.

**Действия:**  
- Добавить проверку на `out.empty()` после распаковки и вернуть `false`, если данные пусты.

---
