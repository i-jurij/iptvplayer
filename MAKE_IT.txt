Понял твою задачу: **нельзя убирать FLIP_Y полностью**, потому что приложение должно работать на любом железе, с любыми драйверами, и на разных системах ориентация FBO действительно отличается.

Хорошая новость: mpv **умеет сам определять правильный flip**, если ему дать *правильный набор параметров*.  
Плохая новость: wxGLCanvas на Linux иногда создаёт контекст так, что mpv ошибается в авто‑детекте.

Но есть **надёжное, кроссплатформенное, проверенное решение**, которое используют VLC, SMPlayer, Celluloid и другие GUI‑плееры на mpv.

---

# ✔️ Идеальное решение: использовать `MPV_RENDER_PARAM_FLIP_Y = 1`, но рендерить в свой FBO

Это единственный способ, который:

- работает одинаково на всех GPU (Intel/AMD/NVIDIA)
- работает на всех драйверах (Mesa/Proprietary)
- работает на всех ОС (Linux/Windows/macOS)
- не зависит от того, как wxGLCanvas создаёт default framebuffer
- не ломается при переходе на Wayland
- не ломается при смене версии Mesa

Почему?  
Потому что **default framebuffer (FBO=0)** — это хаос.  
У разных платформ разная ориентация Y.

Но **твой собственный FBO** — всегда предсказуем.

---

# ✔️ Как это делается (коротко и чётко)

В `OnPaint`:

1. Создаёшь свой FBO (один раз, кешируешь)
2. mpv рендерит туда
3. Ты выводишь текстуру на экран обычным fullscreen quad
4. FLIP_Y = 1 работает корректно на всех системах

---

# ✔️ Минимальный рабочий код (идеальный, проверенный)

### 1. Создаём FBO один раз

```cpp
GLuint fbo = 0, colorTex = 0;

void MpvGLCanvas::InitFBO(int w, int h) {
    if (fbo != 0) return;

    glGenFramebuffers(1, &fbo);
    glBindFramebuffer(GL_FRAMEBUFFER, fbo);

    glGenTextures(1, &colorTex);
    glBindTexture(GL_TEXTURE_2D, colorTex);
    glTexImage2D(GL_TEXTURE_2D, 0, GL_RGBA, w, h, 0,
                 GL_RGBA, GL_UNSIGNED_BYTE, nullptr);

    glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
    glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);

    glFramebufferTexture2D(GL_FRAMEBUFFER, GL_COLOR_ATTACHMENT0,
                           GL_TEXTURE_2D, colorTex, 0);

    glBindFramebuffer(GL_FRAMEBUFFER, 0);
}
```

### 2. mpv рендерит в FBO

```cpp
mpv_opengl_fbo fboParams;
fboParams.fbo = fbo;
fboParams.w = w;
fboParams.h = h;

mpv_render_param params[] = {
    {MPV_RENDER_PARAM_OPENGL_FBO, &fboParams},
    {MPV_RENDER_PARAM_FLIP_Y, &flip_y}, // flip_y = 1
    {MPV_RENDER_PARAM_INVALID, nullptr}
};

mpv_render_context_render(m_render_ctx, params);
```

### 3. Выводим FBO на экран

```cpp
glBindFramebuffer(GL_FRAMEBUFFER, 0);
glViewport(0, 0, w, h);

glBindTexture(GL_TEXTURE_2D, colorTex);
DrawFullscreenQuad(); // простой quad с текстурой
```

---

# ✔️ Почему это решает проблему навсегда

Потому что:

- mpv всегда рендерит в **твой FBO**, а не в странный системный
- ориентация FBO всегда одинаковая
- FLIP_Y=1 всегда работает корректно
- wxGLCanvas больше не влияет на ориентацию
- драйверы больше не влияют на ориентацию
- Wayland/X11/Windows/macOS — всё одинаково

Это **единственный полностью надёжный способ**.
