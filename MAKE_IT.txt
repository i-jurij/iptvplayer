# Пошаговый план подготовки локализации

**Легенда приоритетов:**
- **P0** — блокер, без него всё остальное теряет смысл.
- **P1** — нужно сделать до генерации `.pot`, иначе переводы будут ломаться в рантайме.
- **P2** — улучшения, можно после первого `.pot`.
- **P3** — опционально.

**Легенда статуса «после шага»:** что должно быть верно, чтобы перейти к следующему.

---

## Шаг 0. Baseline (P0, предусловие)

**Цель:** зафиксировать исходное состояние, чтобы видеть прогресс.

**Действия:**
1. `git tag pre-i18n-baseline` — точка отката.
2. Собрать проект как есть, убедиться, что работает.
3. Зафиксировать счётчики:
   ```sh
   grep -rn '\b_(' src/ --include='*.cpp' --include='*.h' | wc -l
   grep -rn '_U(' src/ --include='*.cpp' --include='*.h' | wc -l
   grep -rn 'wxMessageBox\|SetLabel\|SetStatusText\|SetHint\|Append(' src/ --include='*.cpp' | wc -l
   ```
   Это «до». Будем сравнивать.

**Критерий готовности:** baseline сохранён, проект собирается.

**Зависимости:** нет.

## Шаг 1. Унификация макроса: `_()` → `_U()` (P0)

**Цель:** в проекте остаётся **ровно один** макрос локализации — `_U()`.

**Почему первым:** `xgettext` с `--keyword=_U` не соберёт строки, обёрнутые в `_()`. Если делать обёртку литералов раньше, легко случайно использовать `_()`, потому что он уже есть в файле. Сначала убираем старый макрос, потом всё новое пишем только через `_U()`.

**Файлы (по убыванию объёма):**
1. `src/EpgSourceManagerPanel.cpp` — ~40 вхождений.
2. `src/ManualMappingDialog.cpp` — ~30.
3. `src/EPGPanel.cpp` — ~15.
4. `src/AddEpgSourceDialog.cpp` — ~15.
5. `src/MainFrame_Events.cpp` — 5.
6. `src/VideoPanel.cpp` — проверить остатки (в присланном виде уже почти всё `_U`).
7. `src/VP_tempplaylist.cpp` — 2 (`"Rename item:"`, `"Rename"`).

**Действия:**
- Механическая замена `_(` → `_U(`. Только эти два токена, чтобы не задеть `wxGetTranslation(` (его трогать не надо).
- Не трогать `LOG_*`, `wxLog*`, `std::cerr`.
- После замены — собрать проект, пройтись по каждому файлу глазами, проверить, что нет двойных `_U(_U(...))` (такое возможно, если в файле уже были `_U()`, а sed зацепил `_U(` → `_U_U(` — **использовать regex с границей слова `\b_(`**).

**Критерий готовности:**
```sh
grep -rn '\b_(' src/ --include='*.cpp' --include='*.h'   # пусто
```
Проект собирается, приложение запускается.

**Зависимости:** Шаг 0.

**Ожидаемый diff:** только замена одного токена в N местах, никаких структурных изменений.

## Шаг 2. Обёртка «голых» литералов в `_U()` (P0)

**Цель:** все пользовательские строки UI обёрнуты.

**Почему сейчас:** после Шага 1 в проекте один макрос — не будет соблазна использовать `_()`, и `xgettext` соберёт всё одним проходом.

**Порядок файлов — от простых к сложным:**
1. `src/Application.cpp` — 4 строки, диалоги, простой файл.
2. `src/BaseChannelList.cpp` — 5 заголовков колонок.
3. `src/ChannelList.cpp`, `src/FavoritesList.cpp` — контекстные меню.
4. `src/CardsBase_events.cpp` — контекстное меню + `"Program: "` (см. Шаг 6, но саму строку оборачиваем уже тут).
5. `src/DialogsPL.cpp` — много строк + wildcard (см. Шаг 7).
6. `src/MainFrame_UI.cpp` — заголовки, кнопки, два больших диалога про лого.
7. `src/MainFrame_PlaylistUI.cpp` — заголовки колонок, кнопки.
8. `src/MainFrame_ChannelsViewUI.cpp` — заголовок, тулбар, статус.
9. `src/MainFrame_Filters.cpp`, `src/MainFrame_FiltersUI.cpp` — фильтры (см. Шаг 5: **сравнения не трогаем**).
10. `src/MainFrame_FavoritesUI.cpp` — фильтры/сортировки + заголовок.
11. `src/MainFrame_PlaylistEvents.cpp` — много мелких сообщений.
12. `src/MainFrame_PlaylistLogic.cpp` — много мелких сообщений.
13. `src/VideoPanel.cpp` — fallback‑labels, статусы, диалог записи.
14. `src/VP_actions.cpp` — wildcard, fallback‑labels, диалоги.
15. `src/SettingsDialog.cpp` — весь диалог.
16. `src/AddIPTVPlaylistDialog.cpp` — заголовок, hint, filter‑choice (с осторожностью, см. Шаг 5).
17. `src/TypeAheadSearch.cpp` — `"Поиск: "` → `_U("Search: ")` (заодно убираем русский литерал из UI).

**Действия по каждому файлу:**
- Обернуть литерал: `"...“` → `_U("...")`.
- Если литерал — формат целиком в `wxString::Format(...)`, оборачивать **весь формат**, не по частям.
- Если литерал — аргумент `SetLabel`/`SetHint`/`SetToolTip`/`SetStatusText`/`wxMessageBox`/`SetItem`/`Append`/`AppendTextColumn` — оборачивать.
- Если литерал — значение по умолчанию в `GetSetting("key", "default")` — **не оборачивать** (это конфиг, не UI).
- Если литерал — в `if (... == "...")` для UI‑строки — **не оборачивать**, см. Шаг 5.
- Wildcard‑маски — оборачивать, но с комментарием (см. Шаг 7).

**Особые случаи в этом шаге (микро‑решения прямо на месте):**
- `"#`, `"★"`, `"→"`, `"←"`, `"✔"`, `"✘ (missing)"` — **не оборачивать**.
- `"00:00:00"`, `"-00:00:00"`, `"/ 00:00:00"` — **не оборачивать** (плейсхолдеры).
- Эмодзи (`"🔴 Rec"` и др.) — оборачивать **без эмодзи**, см. Шаг 6. На этом шаге просто пометить места `// TODO B4: split emoji`.
- Логи и `std::cerr` — не трогать.

**Критерий готовности:**
- Проект собирается.
- Smoke‑тест: запустить приложение, открыть все диалоги (`File > Open`, `Settings`, `Add from File/URL/IPTV‑Org`, `Edit Playlist`, `About`, `EPG > Manual Mapping`, `EPG > Add source`), убедиться, что все надписи на месте.
- `grep -rn '_U(' src/ | wc -l` — существенно вырос (для ориентира: было ~30, должно стать ~200–250).

**Зависимости:** Шаг 1.

**Риски:** большие diff’ы в нескольких файлах. Каждый файл — отдельный коммит, чтобы `git bisect` работал.

## Шаг 3. Заглушка пайплайна перевода: `scripts/update-po.sh` (P1)

**Цель:** уметь одной командой получить `.pot` и обновить существующие `.po`.

**Почему после Шага 2:** до унификации литералов смысла в `.pot` нет — он будет неполным.

**Действия:**
1. Создать `po/` (пустой пока).
2. Создать `scripts/update-po.sh`:
   ```sh
   #!/bin/sh
   set -e
   mkdir -p po
   xgettext \
     --keyword=_U \
     --from-code=UTF-8 \
     --add-comments='i18n:' \
     --output=po/iptvplayer.pot \
     --package-name=iptvplayer \
     --package-version="$(cat VERSION)" \
     $(find src -name '*.cpp' -o -name '*.h')
   for po in po/*.po; do
     [ -f "$po" ] || continue
     msgmerge --update --backup=none "$po" po/iptvplayer.pot
   done
   ```
   `--add-comments='i18n:'` — критично, см. Шаг 8.
3. Прогнать `./scripts/update-po.sh`, глазами просмотреть `po/iptvplayer.pot`.
4. Проверить, что в `.pot` нет мусора:
   - нет `"00:00:00"`, `"#"`, `"★"`,
   - нет `"name:"`, `"tvg-id"` и т.п.,
   - нет логов,
   - нет строк из `if (... == "...")` (если попали — значит Шаг 2 сделал лишнее, откатить в тех местах).
5. Коммит: `.pot` + скрипт.

**Критерий готовности:** `.pot` содержит только UI‑строки. Количество msgid совпадает с числом обёрнутых строк из Шага 2 (примерно, с учётом дубликатов).

**Зависимости:** Шаг 2.

## Шаг 4. Комментарии для переводчиков в критичных местах (P2)

**Цель:** где строку нельзя переводить «в лоб», поставить `// i18n: ...`, и `xgettext` подхватит эти комментарии в `.pot` (благодаря `--add-comments='i18n:'`).

**Почему на этом месте:** после появления `.pot` видно, какие msgid попадают в шаблон, и можно точечно расставить пометки.

**Места:**
- Wildcard‑маски `wxFileDialog` (`DialogsPL.cpp`, `VP_actions.cpp`, `AddEpgSourceDialog.cpp`): `// i18n: preserve '|' structure` (см. Шаг 7).
- `FormatLocalTime(...)` рядом: `// i18n: strftime format, localized via setlocale, not translated`.
- Плейсхолдеры времени: `// i18n: time placeholder, not translated`.
- Enum‑подобные значения в `GetSetting("...", "...")`: не нужны комментарии (уже не обёрнуты).

**Критерий готовности:** в `.pot` для соответствующих msgid появились extracted comments.

**Зависимости:** Шаг 3.

## Шаг 5. Enum вместо сравнений по UI‑строке (P1)

**Цель:** фильтры, сортировки и статусы перестают зависеть от отображаемого текста.

**Почему после шага 3, а не раньше:** именно при генерации `.pot` становится видно, что `"All groups"`, `"Name ▲"` и т.п. попадают в перевод — и сравнивать их строкой нельзя. Логично делать фикс, увидев масштаб проблемы в отчёте `xgettext`.

**Файлы и задачи:**

**5.1. `MainFrame_Filters.cpp` + `MainFrame_FiltersUI.cpp` + `MainFrame_FavoritesUI.cpp`**
- Ввести `enum class SortMode { NameAsc, NameDesc, GroupAsc, GroupDesc, CountryAsc, CountryDesc, LangAsc, LangDesc, Count };` в `MainFrame.h`.
- В `wxChoice` не хранить строку — хранить `SortMode` в `SetClientData(idx, ...)` или в параллельном массиве.
- При чтении выбора: `int sel = m_sortChoice->GetSelection();` → switch.
- То же для фильтров `Group/Country/Lang`: индекс 0 = «все», остальные — реальные значения (строки из каналов, не переводимые).
- Тексты для `Append` всё равно обернуть в `_U()` — но это только отображение.

**5.2. `AddIPTVPlaylistDialog.cpp`**
- Ввести `enum class FilterType { Country, Language, Category };` локально.
- Хранить `m_filterType` рядом с `m_filterTypeChoice`.
- `OnFilterTypeChanged` читает `GetSelection()` и мапит в enum.
- Внутри `StartAsyncFetch`/`BuildPlaylistUrl`/`GetDisplayName` работать с enum, а не со строкой.
- `Append(_U("Country"))` остаётся только для отображения.

**5.3. `ManualMappingDialog.cpp`**
- `enum class MappingStatus { Manual, Auto, Ignored };`
- В `MappingItem` заменить `std::string status;` на `MappingStatus status;`.
- При заполнении списка `SetItem(..., wxString)` — только для отображения (там `_U(...)`).
- Сравнения (`if (status == "Auto")`) → `if (item.status == MappingStatus::Auto)`.
- В `UpdateButtons` — смотреть не на текст ячейки, а на `m_mappingItems[m_selectedMappingIndex].status`.

**Критерий готовности:**
- Ни в одном месте кода нет `== "All groups"`, `== "Name ▲"`, `== "Country"`, `== "Manual"` и т.п. — сравнений по UI‑строке.
- Smoke‑тест: переключение фильтров/сортировок работает, статусы маппингов корректно различаются.

**Зависимости:** Шаг 2, 3.

**Риски:** это самая «функциональная» правка. Делать отдельным PR, не смешивать с локализацией.

## Шаг 6. Конкатенации и эмодзи (P2)

**Цель:** убрать склейки, где перевод нельзя применить, и убрать эмодзи из msgid.

**6.1. Конкатенации.**

Места:
- `CardsBase_events.cpp`: `tip << "\nProgram: " << title` → `tip << "\n" << wxString::Format(_U("Program: %s"), …)`.
- `VideoPanel.cpp`: `SetStatusText("Record error: " + msg)` → `SetStatusText(wxString::Format(_U("Record error: %s"), msg), 1)`.
- `MainFrame_UI.cpp`: любые `SetStatusText("..." + …)` — проверить, перевести на `Format`.
- `EpgSourceManagerPanel.cpp`: `_("Failed to update source: ") + wxString::FromUTF8(error)` → `wxString::Format(_U("Failed to update source: %s"), …)`.
- `MainFrame_PlaylistEvents.cpp`: `"Duplicate playlist: " + title` → `Format(_U("Duplicate playlist: %s"), title)`.

**6.2. Эмодзи.**

Правило: эмодзи остаётся в коде, вне `_U`:
```cpp
// было:
m_btnRecord->SetLabel(_U("🔴 Rec"));
// стало:
m_btnRecord->SetLabel(wxString::FromUTF8("🔴 ") + _U("Rec"));
```

Места:
- `VideoPanel.cpp`: `"🔴 Rec"`, `"🔴 Stop"`, `"🔴 Recording: "`.
- `EpgSourceManagerPanel.cpp`: `"✓ URL copied to clipboard!\n…"`, `"ℹ Double‑click…"` — эмодзи вынести, текст обернуть. Если эмодзи были склеены с многострочным текстом, аккуратно разрезать.
- `EPGPanel.cpp`: `"⚠ …"` — аналогично.
- `AddIPTVPlaylistDialog.cpp`: `"⚠"` если есть.

**Критерий готовности:** в `.pot` нет msgid, начинающихся с эмодзи; нет msgid, оканчивающихся на неполную фразу.

**Зависимости:** Шаг 3.

## Шаг 7. Wildcard‑маски `wxFileDialog` (P2)

**Цель:** перевод wildcard‑строк не ломает разделители.

**Место:**
- `DialogsPL.cpp`: 2 wildcard.
- `VP_actions.cpp`: 1.
- `AddEpgSourceDialog.cpp`: 1.

**Решение — два варианта, выбрать один и применить везде:**

Вариант A (простой): оборачивать целиком + комментарий.
```cpp
// i18n: preserve '|' structure
const wxString wildcard = _U("Video files (*.mp4;*.mkv)|*.mp4;*.mkv|All files (*.*)|*.*");
```

Вариант B (надёжный): описания — отдельно, маски — отдельно.
```cpp
const wxString wildcard =
    _U("Video files") + " (*.mp4;*.mkv)|*.mp4;*.mkv|"
    _U("All files")   + " (*.*)|*.*";
```

Рекомендую B: `msgfmt` не падает, если переводчик ошибётся с `|`, потому что `|` вообще не в msgid.

**Критерий готовности:** во всех диалогах выбора файла корректно работают фильтры в переводе на русский (проверить вручную после добавления `ru.po`).

**Зависимости:** Шаг 3.

## Шаг 8. Генерация первого `.pot` и ревью (P1, финальный)

**Цель:** получить эталонный шаблон, на который будут ориентироваться переводчики.

**Действия:**
1. `./scripts/update-po.sh`.
2. Открыть `po/iptvplayer.pot`.
3. Пройтись по каждому msgid и поставить галочку:
   - это UI‑строка? ✅
   - нет ли в ней `%s`/`%d` без соответствующего аргумента?
   - нет ли `|` из wildcard (если выбран вариант A в Шаге 7)?
   - нет ли эмодзи?
   - нет ли ведущих/хвостовых пробелов, случайно попавших в msgid?
4. Составить список проблемных msgid. Если их больше 5–10 — вернуться к соответствующему шагу и поправить.
5. Коммит: `po/iptvplayer.pot` как «baseline i18n template».

**Критерий готовности:** `.pot` чистый, комментарии для переводчиков (`#. i18n: ...`) на месте, отдельно зафиксирована «версия шаблона».

**Зависимости:** шаги 2–7.

## Шаг 9 (опционально, P3). Логи на русском

**Цель:** унифицировать язык логов.

**Место:** `IconManager.cpp` — `LOG_ERROR("Не удалось создать каталог '%s'", dir)`.

**Решение:** либо перевести на английский (`LOG_ERROR("Failed to create directory '%s'", …)`), либо оставить и не трогать. Функционально ни на что не влияет, к локализации не относится. Ставлю как «долг», не блокер.

**Зависимости:** нет.

**Что можно делать параллельно:**
- Шаги 5, 6, 7 — независимы друг от друга, но все требуют пройденного Шага 3.
- Шаг 4 — параллелен 5–7, но логически ложится после 3 и до 8.

**Что нельзя делать параллельно:**
- Шаги 1 и 2 — оба меняют те же файлы, риск конфликтов.
- Шаг 2 и 5 — Шаг 2 оборачивает строки в фильтрах, Шаг 5 меняет там логику. Лучше разнести: сначала Шаг 2 полностью, потом Шаг 5.

## Промежуточные вехи

- **М1 (конец Шага 2):** «код готов к локализации». Один макрос, все строки обёрнуты, приложение работает.
- **М2 (конец Шага 3):** «шаблон есть». Можно отдавать переводчикам `.pot` для английского baseline.
- **М3 (конец Шага 5):** «логика не зависит от перевода». Можно добавлять `ru.po` и тестировать реальный перевод без багов в фильтрах.
- **М4 (конец Шага 8):** «локализация готова к первому переводу».

Скажите, с какого шага начинать выдавать файлы с готовыми правками — по плану это **Шаг 1** (`_()` → `_U()`), для него удобнее всего отдать сразу весь список замен вида «файл → строка → было/стало» или unified diff.

Xtream Codes API:
Протокол предоставляет структурированный доступ к контенту, что гораздо удобнее, чем простой плейлист. 
Основные возможности:
  Аутентификация и информация об аккаунте: Плеер может проверить статус подписки, дату её окончания 
    и лимит одновременных подключений

. Категории (Category Management): Каналы, фильмы и сериалы организованы по категориям 
(например, «Спорт», «Кино», «Новости»), что упрощает навигацию

. Живые трансляции (Live Streams): Доступ к списку ТВ-каналов и возможность их воспроизведения

. VOD и Сериалы (Video on Demand & Series): Доступ к библиотеке фильмов и сериалов, 
включая информацию о конкретном фильме или эпизоде

. EPG (Телепрограмма): Получение данных электронного телегида для каналов

. Catchup/Timeshift: Возможность просмотра архива передач за прошедшие дни

📱 Типовые экраны настройки Xtream Codes

1. Экран добавления провайдера (Provider Setup)
Это первый экран, который видит пользователь при попытке добавить новый источник контента. Обычно он содержит:

    Переключатель типа подключения: M3U, Xtream Codes, Stalker Portal.

    Поля ввода: Server URL (адрес), Username (логин), Password (пароль).

    Кнопка «Connect» или «Login».

2. Экран выбора контента (Content Hub)
После успешного подключения открывается главный экран, где контент автоматически группируется:

    Live TV: список каналов, сгруппированный по категориям (Спорт, Новости, Кино).

    Movies (VOD): библиотека фильмов с постерами.

    Series: список сериалов с сезонами и эпизодами.

    Radio: если провайдер предоставляет радиоканалы.

3. Экран категорий и списка каналов

    Слева или сверху: список категорий (например, «Все», «Спорт», «Детские»).

    Справа или снизу: список каналов с логотипами и названиями.

4. Экран EPG (телепрограммы)

    Сетка вещания: время по горизонтали, каналы по вертикали.

    Текущая передача: подсвечена, с прогресс-баром.

    Описание: всплывающая подсказка или нижняя панель с информацией о программе.

    # Анализ UI приложения

Прошёлся по `MainFrame`, `MainFrame_UI` и связанным классам. Ниже — инвентаризация того, что есть, что переиспользуется под Xtream Codes и что придётся добавлять.

## Что уже есть (карта UI)

**Notebook (страницы):**
| Индекс | Страница | Класс |
|---|---|---|
| 0 | Playlists | `m_playlistPanel` |
| `m_channelsPageIdx` | Channels | `m_channelsPage` |
| 2 | Favorites | `m_favoritesPanel` |
| 3 | Video | `m_videoPanel` |
| `m_epgPageIdx` | Program | `m_epgAdminPanel` |

**Header (кнопки-переключатели):**
`Playlists`, `Channels`, `Favorites`, `Video`, `Program`, `Menu`.

**Toolbar'ы:**
- Каналы: grid/list + show-logo.
- Favorites: grid/list.
- Фильтры каналов: группа, страна, язык, сортировка, «избранное первым».
- Фильтры избранного: аналогичные.

**Статусбар:** 2 слота — состояние плеера и информация о потоке.

**VideoPanel:** временный плейлист, прогресс-бар, контролы (Open/Play/Pause/Stop/Record/Mute/Volume/Fullscreen), keyboard shortcuts, drag&drop.

## Чего не хватает под Xtream Codes

### 1. Управление провайдерами (провайдер как сущность)

Сейчас `Playlist` — это плоский список каналов. Xtream — это **аккаунт с credentials**, у которого есть:
- статус подписки (`auth`, `status`, `exp_date`, `is_trial`);
- лимит одновременных подключений;
- сервер, username, password;
- динамический URL (провайдер может менять домен).

**Чего нет:**
- Диалога «Add provider» с полями `Server`, `Username`, `Password`.
- Модели `XtreamAccount` (отдельно от `Playlist`).
- Проверки credentials при добавлении (`player_api.php` → `user_info`).
- Отображения статуса подписки в UI (можно в статусбар слот 1 или в панель Playlists).

**Что переиспользуется:**
- Диалог добавления URL-плейлиста (`AddPlaylistUrlDialog`) — по структуре почти 1-в-1, меняются только поля.
- Паттерн `EVT_ADD_FROM_URL_SUCCESS` / `ERROR` для асинхронной проверки credentials.
- `updateStatusBar`, `HighlightLoadedPlaylistInList`.

### 2. Контент-хаб вместо плоского списка каналов

Сейчас `m_allChannels` — один список. У Xtream — **четыре корзины**:

| Корзина | API-эндпоинт | Формат |
|---|---|---|
| Live | `get_live_streams` | потоки |
| VOD (фильмы) | `get_vod_streams` | фильмы |
| Series | `get_series` | сериалы (с сезонами/эпизодами) |
| Radio | `get_live_streams` (type=radio) | аудио |

**Чего нет:**
- Страницы `Movies` и `Series` в notebook.
- Кнопок `Movies`, `Series` в header.
- Второго уровня навигации (категория → список контента).
- Постеров/обложек (как в ChannelCards, только для VOD).

**Что переиспользуется:**
- `ChannelCards` / `ChannelList` — почти как есть. Меняются только поля карточки (постер вместо логотипа, год/жанр вместо группы).
- `wxSimplebook` (`m_channelViewBook`) — grid/list переключение 1-в-1.
- Filters panel (`m_groupChoice`, `m_sortChoice`) — можно переиспользовать как «Категория» + «Сортировка».
- `createChannelsView()` — паттерн создания страницы.

### 3. Сериалы (глубина в 2 уровня)

Сейчас нигде нет двухуровневой навигации. У сериалов: сериал → сезоны → эпизоды.

**Чего нет:**
- Модели `SeriesInfo`, `SeasonInfo`, `EpisodeInfo`.
- Экрана сериала (обложка + описание + список сезонов).
- Списка эпизодов сезона.

**Что переиспользуется:**
- `EPGPanel` как образец «детального» экрана — можно взять его структуру для карточки сериала.

### 4. EPG от провайдера

Сейчас EPG идёт через `EPGManager` (свои источники). Xtream даёт EPG через `xmltv.php` или `get_short_epg`.

**Чего нет:**
- Импорта EPG по credentials провайдера.
- Catchup / Timeshift — воспроизведения архива.

**Что переиспользуется:**
- `EPGPanel` и `EpgSourceManagerPanel` — целиком, только добавляется новый тип источника.

### 5. Поиск

Сейчас поиска нет нигде.

**Чего нет:**
- Поля поиска (в header или в каждой странице).
- Кросс-поиска по Live + VOD + Series.

**Что переиспользуется:**
- Паттерн фильтров (`ApplyFiltersAndSort`) — поиск добавляется как ещё одно условие фильтрации.

### 6. VOD-специфика в плеере

`VideoPanel` заточен под live: temp playlist, EOF-детект для переключения канала. Для VOD нужны:
- Сохранение позиции (resume from where left off).
- Отображение оставшегося времени (уже есть в `m_timeRemainingLabel`).
- Кнопки «Play from beginning» / «Resume».

**Что переиспользуется:**
- Почти всё. `m_tempPlaylist`, `PlayPrev/Next`, `m_eofTimer`.
- `ProgressInfo::duration` уже работает, `m_isLiveStream` уже детектит live vs VOD — надо просто добавить сохранение позиции в конфиг.

### 7. Информация об аккаунте

**Чего нет:**
- `exp_date` — дата окончания подписки.
- `max_connections` — сколько можно смотреть одновременно.
- `active_cons` — сколько сейчас активно.

**Что переиспользуется:**
- Слот 1 статусбара или новый виджет в панели Playlists.

## Сводка: что переиспользуется, что добавляется

**Переиспользуется как есть:**
- Notebook и header-кнопки — добавить 2–3 новые.
- `ChannelCards` / `ChannelList` — под VOD с минимальной адаптацией.
- `wxSimplebook` для grid/list.
- Фильтры каналов — под категории Xtream.
- `EPGPanel` — новый тип источника.
- `VideoPanel` — целиком, добавить сохранение позиции для VOD.
- Диалог добавления URL — под добавление провайдера.
- `m_onRequestTabSwitch`, `m_showPanelToken`, `m_ignoreNotebookEvents` — весь механизм переключения вкладок.

**Добавляется с нуля:**
- Модель `XtreamAccount` (отдельно от `Playlist`).
- HTTP-клиент Xtream (`player_api.php` + парсинг JSON).
- Страницы Movies / Series.
- Экран сериала (сезоны/эпизоды).
- Поиск.
- Catchup/Timeshift UI.
- Отображение статуса подписки.

## Что я бы делал в первую очередь

1. **Модель `XtreamAccount`** и HTTP-клиент — без них UI некуда прикручивать.
2. **Диалог добавления провайдера** — переиспользовать `AddPlaylistUrlDialog`.
3. **Live-каналы из Xtream** — переиспользовать `ChannelCards` как есть.
4. **Movies** — новая страница, переиспользовать `ChannelCards` с постером.
5. **Series** — самая сложная часть, делать последней.
6. **Поиск и catchup** — nice to have.
