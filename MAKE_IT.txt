## План рефакторинга `ManualMappingDialog` (поэтапно)

### Общий подход
Рефакторинг выполняется поэтапно. Каждый этап завершается полной сборкой и тестированием. Если на каком-то этапе возникают проблемы – откат только к началу этапа, а не всего диалога.

---

## Этап 1: Оптимизация `PopulateMappings()` (один запрос вместо N)

**Цель:** заменить N запросов к БД (по одному на каждый канал) на один запрос, получающий все маппинги для плейлиста.

**Изменения:**

1. В `EPGData.h` добавить структуру:
   ```cpp
   struct MappingEntry {
       std::string epgId;
       bool isManual = false;
       bool ignored = false;
   };
   ```

2. В `EPGDatabase.h` объявить метод:
   ```cpp
   bool GetAllMappings(const std::string &playlistId,
                       std::unordered_map<std::string, MappingEntry> &out);
   ```

3. В `EPGDatabase.cpp` реализовать метод (один SQL-запрос).

4. В `EPGManager.h` объявить обёртку:
   ```cpp
   std::unordered_map<std::string, MappingEntry> GetAllMappingsForPlaylist(const std::string &playlistId);
   ```

5. В `EPGManager.cpp` реализовать обёртку (вызывает `EPGDatabase::GetAllMappings`).

6. В `ManualMappingDialog.cpp` переписать `PopulateMappings()`:
   - Удалить цикл с `GetMappingEntry` и `IsIgnored`.
   - Вместо него получить все маппинги через `m_epgMgr->GetAllMappingsForPlaylist(playlistId)`.
   - Для каждого канала проверять наличие ключа в полученной карте (по tvgId, нормализованному имени, сырому имени).
   - Заполнять список маппингов напрямую, как раньше, но без дополнительных запросов.

**Проверка:**  
Открыть диалог ручного маппинга. Убедиться, что список маппингов отображается корректно и соответствует данным в БД. Время открытия должно уменьшиться (особенно при большом количестве каналов).

---

## Этап 2: Сортировка списков

**Цель:** добавить сортировку по имени в верхних списках (плейлист и EPG) и сортировку по клику на заголовок в нижнем списке.

### 2.1. Сортировка верхних списков (статическая)

1. В `PopulatePlaylistChannels()` перед вставкой отсортировать вектор `channels` по `getName()` (регистронезависимо, через `wxStricmp`).
2. В `PopulateEpgChannels()` перед вставкой отсортировать вектор пар по `display_name` (аналогично).

**Проверка:**  
Открыть диалог – верхние списки должны быть отсортированы по алфавиту.

---

### 2.2. Сортировка нижнего списка (интерактивная)

1. В `ManualMappingDialog.h` добавить:
   ```cpp
   int m_sortColumn = 1;     // по умолчанию колонка "Имя канала"
   bool m_sortAscending = true;
   void ApplySortToMappings();
   void OnColumnClick(wxListEvent &event);
   static int SortComparator(long item1, long item2, long sortData);
   ```

2. В конструкторе привязать `wxEVT_LIST_COL_CLICK` к `OnColumnClick`.

3. Реализовать `SortComparator` как статический метод (без захвата `this`) с проверкой колонок.

4. Реализовать `ApplySortToMappings()`, вызывающий `SortItems(SortComparator, (long)this)`.

5. В конце `PopulateMappings()` после заполнения вызвать `ApplySortToMappings()` (сортировка по умолчанию).

**Проверка:**  
Открыть диалог – нижний список отсортирован по имени канала. Кликнуть на любой заголовок – сортировка должна меняться.

---

## Этап 3: Поиск в списках

**Цель:** добавить мгновенный поиск над каждым списком.

### 3.1. Добавление элементов управления

1. В `ManualMappingDialog.h` добавить:
   ```cpp
   wxSearchCtrl *m_searchPlaylist;
   wxSearchCtrl *m_searchEpg;
   wxSearchCtrl *m_searchMappings;
   
   std::vector<Channel> m_allPlaylistChannels;
   std::vector<std::pair<std::string, std::string>> m_allEpgChannels;
   struct MappingRow { wxString tvgId, channelName, epgId, epgName, status, key; };
   std::vector<MappingRow> m_allMappingRows;
   
   void ApplyFilterAndSortPlaylist();
   void ApplyFilterAndSortEpg();
   void ApplyFilterAndSortMappings();
   void OnSearchPlaylist(wxCommandEvent &);
   void OnSearchEpg(wxCommandEvent &);
   void OnSearchMappings(wxCommandEvent &);
   ```

2. В конструкторе создать `wxSearchCtrl` над каждым списком (использовать `Insert(0, ...)` в соответствующих `wxStaticBoxSizer`).

3. Привязать `wxEVT_TEXT` к соответствующим обработчикам.

### 3.2. Хранилища и методы фильтрации

1. `PopulatePlaylistChannels()`: сохранять копию всех каналов в `m_allPlaylistChannels`, затем вызывать `ApplyFilterAndSortPlaylist()`.

2. `PopulateEpgChannels()`: аналогично – сохранять в `m_allEpgChannels`, затем вызывать `ApplyFilterAndSortEpg()`.

3. `PopulateMappings()`: вместо прямой вставки заполнять `m_allMappingRows` (вектор структур), затем вызывать `ApplyFilterAndSortMappings()`.

4. В `ApplyFilterAndSortPlaylist()`: очищать список, проходить по `m_allPlaylistChannels`, применять фильтр (поиск по имени), вставлять отфильтрованные строки, затем применять сортировку (если нужна) – но сортировка уже есть в верхних списках, поэтому достаточно просто вставлять в отсортированном порядке.

5. Аналогично для EPG и маппингов. Для маппингов в `ApplyFilterAndSortMappings()` после вставки вызывать `ApplySortToMappings()`.

### 3.3. Обновление при изменении маппингов

- В обработчиках (`OnAddMapping`, `OnRemoveMapping`, `OnIgnore`, `OnUnignore`) после изменения данных вызывать `PopulateMappings()`, которая перестроит хранилище и применит фильтр и сортировку.

**Проверка:**  
Открыть диалог. Ввести текст в любое поле поиска – соответствующий список должен мгновенно фильтроваться. Очистить поле – список должен вернуться к полному набору.

---

## Итоговые замечания

- Каждый этап независим и может быть протестирован отдельно.
- После завершения всех этапов диалог будет быстрым (один запрос к БД) и удобным (сортировка, поиск).
- Все изменения локализованы в `ManualMappingDialog`, `EPGDatabase`, `EPGManager` и не затрагивают остальной код.
========================================
Логические моменты
SetManualMapping: при установке ручного маппинга ты сначала удаляешь любую существующую запись 
(DeleteMappingEntry), а потом вставляешь новую. Это правильно, но стоит помнить: если в БД уже 
был ручной маппинг для другого epgId, он тоже будет удалён. Логически корректно, но может быть 
неожиданно для пользователя.

RemoveChannelMapping: удаляет только ручной маппинг по tvgId. Если ключ был нормализован как "name:...", 
он не удалится этим методом. Это может привести к ситуации, когда ручной маппинг по имени останется висеть.

LoadMappingForPlaylist: проверка хэша плейлиста и количества каналов защищает от несоответствия, 
но если плейлист изменился минимально (например, порядок каналов), маппинг будет признан недействительным. 
Это логически правильно, но может быть слишком строгим.
