### 🗺️ Обновленный подробный пошаговый план

#### Шаг 1. Создание универсальной функции определения сетевого ресурса в `Utils`
*   **Цель:** Единый механизм для различения сетевых URL и локальных путей.
*   **Действие:** Добавить функцию `IsNetworkUrl()`, использующую `wxURI` для проверки схемы. Возвращать `false` для `file://` и строк без схемы, `true` для всех остальных протоколов (`http`, `https`, `ftp`, `smb` и т.д.).

#### Шаг 2. Удаление метода `IsFileSource()` из `AddEpgSourceDialog`
*   **Цель:** Устранить дублирование логики.
*   **Действие:** Удалить метод `IsFileSource()` и заменить все его вызовы на `!IsNetworkUrl()`.

#### Шаг 3. Улучшение валидации и пользовательского опыта в диалоге `AddEpgSourceDialog`
*   **Цель:** Корректная обработка локальных файлов и информирование пользователя.
*   **Действия:**
    *   В `OnOk` использовать `IsNetworkUrl()` для определения типа.
    *   Для локальных путей: преобразовывать в абсолютный путь и проверять существование файла.
    *   Обновить информационную строку, указав поддержку любых URL и локальных путей.

#### Шаг 4. Обновление `SettingsDialog` для использования `IsNetworkUrl`
*   **Цель:** Синхронизировать логику в настройках.
*   **Действие:** В `SettingsDialog::ShowAddEpgSourceDialog` заменить вызов `dlg.IsFileSource()` на `!IsNetworkUrl(urlOrPath)`.

#### Шаг 5. Реализация функции проверки доступности сетевого ресурса `CheckUrlAvailability` в `Utils`
*   **Цель:** Легкая проверка URL перед полной загрузкой.
*   **Действия:**
    *   Создать структуру `UrlAvailabilityResult` с полями: `available`, `httpCode`, `contentLength`, `errorText`.
    *   Создать функцию `CheckUrlAvailability` с параметрами: `url`, `userAgent`, `timeoutSeconds` (по умолчанию 5), `maxCompressedSize` (по умолчанию **250 МБ**) и `maxDecompressedSize` (по умолчанию **1 ГБ**).
    *   Реализовать логику: HEAD-запрос с таймаутом, обработка `Content-Length` и кодов ответа (включая fallback на GET с `Range: 0-0` при ошибке 405). Проверять соответствие размера переданным лимитам.
    *   Добавить логирование результатов.

#### Шаг 6. Интеграция проверки доступности в `EPGManager::LoadFromUrl`
*   **Цель:** Предотвратить загрузку недоступных или слишком больших файлов.
*   **Действия:**
    *   В начале `LoadFromUrl` вызвать `CheckUrlAvailability` с соответствующими лимитами.
    *   При неудаче — установить `m_lastError` и вернуть `false`.
    *   При успехе — продолжить загрузку, сохранив информацию о размере для отображения прогресса.

#### Шаг 7. Исправление `EPGManager::Refresh` для поддержки файловых источников
*   **Цель:** Устранить баг, из-за которого файловые источники не обновлялись.
*   **Действие:** В цикле обновления использовать `IsNetworkUrl()` для вызова `LoadFromUrl()` или `LoadFromFile()` соответственно.

#### Шаг 8. Отображение ошибок и информации в пользовательском интерфейсе
*   **Цель:** Информировать пользователя о результатах проверки и загрузки.
*   **Действия:**
    *   Использовать существующие механизмы (`m_lastError`, статус-бар, колонка "Title" в `EPGPanel`) для отображения ошибок от `CheckUrlAvailability`.
    *   Для вызовов из `SettingsDialog` добавить всплывающие сообщения об ошибках, не блокируя другие операции.

#### Шаг 9. Обновление документации и тестирование
*   **Цель:** Проверить работоспособность изменений.
*   **Действия:** Протестировать сценарии добавления и обновления для локальных файлов, доступных/недоступных URL, а также для файлов, превышающих новые лимиты.

Этот обновленный план учитывает реальные размеры EPG-файлов и делает систему более устойчивой к работе с крупными источниками данных.
