## Полный пошаговый план улучшения UI и функциональности EPG

### 1. Улучшение информативности колонок и проверка доступности источников

**Цель:** Сделать список источников более информативным и добавить асинхронную проверку доступности URL-источников с разумным кэшированием.

**Действия:**
- Переименовать колонки:
  - `"Last Update"` → `"Imported"` (время последнего успешного импорта данных в БД). Если импорта не было – оставляем ячейку **пустой** (не пишем "Never").
  - `"Status"` → `"Availability"` (доступность источника).
- Для локальных файлов: отображать `✔` или `✘ (missing)` (как сейчас).
- Для URL-источников:
  - При загрузке списка проверять кэш:
    - Если есть успешный статус (HTTP 200) → показывать `"online"` (кэш действует до конца сеанса).
    - Если есть неудачный статус (ошибка, таймаут, HTTP != 200) и счётчик попыток < 5 → показывать `"offline"` и обновлять кэш, если прошло более 1 минуты с последней проверки.
    - Если счётчик попыток >= 5 → показывать `"offline (permanent)"` и больше не проверять до перезапуска приложения.
    - Если кэша нет → показывать `"checking..."` и запускать асинхронную проверку.
  - Проверку выполнять через существующую функцию `CheckUrlAvailability` (HEAD-запрос с таймаутом 5 сек).
  - Результаты кэшировать:
    - Успех → кэш до конца сеанса, сбросить счётчик попыток.
    - Неудача → кэш на 1 минуту, инкрементировать счётчик попыток для этого URL.
- При обновлении списка (добавление/удаление источника) – сбрасывать кэш для отсутствующих источников.

---

### 2. Изменение поведения кнопки "Refresh Now"

**Цель:** Обновлять только выбранный источник, а не все.

**Действия:**
- В обработчике `OnRefresh` проверять, есть ли выбранный источник в `m_sourceList`.
- Если выбран – обновить его через `LoadFromUrl` или `LoadFromFile` (с отображением прогресса).
- Если не выбран – ничего не делать (или выводить подсказку "Select a source first").
- (Опционально) добавить контекстное меню для обновления всех источников, если потребуется.

---

### 3. Интерфейсные улучшения (прокрутка, высота таблицы, ширина контролов, кнопка Apply)

**Цель:** Сделать панель удобной и адаптивной.

**Действия:**
- **Вертикальная прокрутка:** сделать `EpgSourceManagerPanel` наследником `wxScrolledWindow` или обернуть всё содержимое в `wxScrolledWindow`, чтобы при переполнении панель прокручивалась.
- **Таблица источников:** установить минимальную высоту `SetMinSize(wxSize(-1, FromDIP(150)))`, но при этом растягивать таблицу по вертикали через `sizer` с пропорцией 1 и `wxEXPAND`, чтобы она занимала всё доступное пространство (при большом количестве строк появляется стандартная прокрутка `wxListCtrl`).
- **Спин-контролы:** увеличить ширину всех `wxSpinCtrl` в секциях "Auto-update settings" и "Match settings" с `FromDIP(80)` до `FromDIP(120)`, чтобы кнопки «вверх/вниз» не обрезались.
- **Кнопка "Apply"** (в настройках матчинга): разместить слева, без центрирования (`wxLEFT` вместо `wxALIGN_CENTER`).

### 4. Архитектура прогресса в `EPGManager`

**Цель:** Создать единый механизм оповещения о ходе выполнения операций (загрузка, распаковка, парсинг, маппинг).

**Действия:**
- В `EPGManager.h` добавить:
  - `enum class EpgProgressStage { None, Downloading, Extracting, Parsing, Matching, Done, Cancelled }`.
  - `struct EpgProgressInfo` с полями: `stage`, `percent` (0–100), `stageText`, `downloadedBytes`, `totalBytes`, `speedBytesPerSec`, `matched`, `totalChannels`, `errorMessage`.
  - Тип `using ProgressCallback = std::function<void(const EpgProgressInfo&)>`.
  - Метод `SetOnProgress(ProgressCallback callback)` и поле `m_progressCallback`.
- В `EPGManager.cpp` в методах `LoadFromUrl`, `ParseAndMerge`, `MatchChannelsAsync` вызывать `m_progressCallback` на ключевых этапах:
  - **Загрузка:** обновлять `percent`, `downloadedBytes`, `totalBytes`, `speedBytesPerSec` (скорость вычислять на основе изменения байт за время).
  - **Распаковка/парсинг:** указывать `stage = Parsing`, обновлять `percent` по мере обработки каналов (можно после каждого канала или пакетами).
  - **Матчинг:** `stage = Matching`, обновлять `percent` на основе `matched/total`.
  - **Завершение:** `stage = Done` (или `Cancelled`, если прервано).

### 5. Перенос индикатора прогресса в `EpgSourceManagerPanel` и интеграция

**Цель:** Переместить прогресс из верхней части главного окна в панель управления EPG, добавить визуализацию этапов и данных о загрузке.

**Действия:**
- В `EpgSourceManagerPanel` добавить:
  - `wxGauge *m_progressGauge` (стиль `wxGA_HORIZONTAL | wxGA_SMOOTH`).
  - `wxStaticText *m_progressLabel` для отображения этапа, процента, размера/скорости (например: `"Downloading (45%) 12.5 MB / 27.8 MB, 2.1 MB/s"`).
  - Разместить их под таблицей источников и над кнопками, растянуть на всю ширину (`wxEXPAND`).
  - Изначально скрыть (`Hide()`), показывать только во время операций.
- В конструкторе или при установке `EPGManager` подписаться на прогресс: `m_epgMgr->SetOnProgress([this](const EpgProgressInfo& info){ OnProgressUpdate(info); })`.
- Реализовать метод `OnProgressUpdate(const EpgProgressInfo& info)`:
  - Обновлять `m_progressGauge` (значение от 0 до 100).
  - Формировать текст для `m_progressLabel` на основе `info.stage` и данных.
  - Обновлять статус-бар главного окна через `m_mainFrame->SetStatusText` (если `m_mainFrame` доступен).
- Добавить метод `SetBusy(bool busy)`:
  - Блокировать/разблокировать все интерактивные элементы панели (кнопки, списки, спин-контролы).
  - Показывать/скрывать прогресс-бар и метку.
  - В зависимости от `busy` переключать состояние панели.

### 6. Интеграция прогресса с операциями и управление блокировкой

**Цель:** Обеспечить согласованную работу прогресса и блокировки во время всех длительных операций.

**Действия:**
- В `EPGManager` при вызове колбэка прогресса передавать актуальные данные.
- В `EpgSourceManagerPanel`:
  - При получении `info.stage != None && info.stage != Done && info.stage != Cancelled` вызывать `SetBusy(true)`.
  - При `stage == Done` или `stage == Cancelled` вызывать `SetBusy(false)`.
  - Обновлять колонку `Imported` после успешного импорта (если известен источник).
- Кнопка **Cancel** (уже есть в панели) должна:
  - Устанавливать флаг `abort` в `DownloadProgress`.
  - Вызывать `CancelMatching()`.
  - Переводить прогресс в состояние `Cancelled` (через колбэк).
- После отмены разблокировать элементы и показать в метке "Cancelled".

### 7. Удаление старого кода прогресса из `MainFrame`

**Цель:** Избавиться от дублирования и устаревших элементов.

**Действия:**
- Удалить `m_gaugeTop` (или переименовать в `m_playlistProgressGauge` и оставить только для обновления плейлистов).
- Удалить таймер `m_epgProgressTimer` и его обработчик `OnEpgProgressTimer`.
- Удалить колбэки `SetOnRefreshStarted` и `SetOnUpdateFinished` (они больше не используются).
- В `MainFrame::OnEPGUpdated` убрать управление гейджем (он теперь в панели).
- При создании `EpgSourceManagerPanel` передать в неё указатель на `MainFrame` (через `SetMainFrame`), чтобы панель могла обновлять статус-бар.
- Убедиться, что прогресс обновления плейлистов продолжает работать через оставшийся `m_playlistProgressGauge`.

### 8. Тестирование всех сценариев

**Цель:** Убедиться, что все изменения работают корректно и не нарушают существующий функционал.

**Проверяемые сценарии:**
- Добавление/удаление источников → обновление колонок, корректное отображение `Imported` и `Availability`.
- Проверка доступности URL: успешный ответ, ошибка, таймаут, большой файл – отображение статуса, кэширование, счётчик попыток.
- Обновление одного источника через кнопку "Refresh Now" (выбранный) – прогресс, блокировка, обновление `Imported`.
- Обновление всех источников (если реализовано) – агрегированный прогресс (или по одному).
- Автоматический матчинг после загрузки – прогресс, блокировка, обновление EPG.
- Ручной матчинг (изменение порогов + Apply) – автоматический пересчёт, прогресс, блокировка.
- Ручной маппинг (диалог) – создание/удаление, сохранение, отображение в EPG.
- Отмена операции через кнопку Cancel – корректный переход в состояние "Cancelled", разблокировка.
- Проверка, что старый код из `MainFrame` не остался и не мешает.
- Проверка, что ошибка `SetStatusText` больше не возникает (исправлено ранее).
